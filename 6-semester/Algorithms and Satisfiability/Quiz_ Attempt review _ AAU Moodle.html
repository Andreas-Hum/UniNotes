Question text

This is an example of a question with a free-form answer that will be graded manually at the exam (not automatically by Moodle).

Consider an array of numbers A[1..n]. We want to find a longest increasing subsequence in this array. Formally, we are looking for a longest sequence A[i1 ] < A[i2 ] < ... < A[ik ], where 1 ≤ i1 < i2 < · · · < ik ≤ n. For example, if A = [7, 4, 5, 2, 8, 3], then the longest increasing subsequence is A[2], A[3], A[5] = 4, 5, 8.

Consider the following greedy algorithm to find the length of a longest increasing subsequence of A:

L = 0
for i = 1 to n
   len = 1
   prev = i
   for j = i+1 to n      // Greedily construct an increasing subsequence starting at i
      if A[j] > A[prev] then 
         len = len+1
         prev = j
   L = max(L, len)
return L

What is the worst-case running time of this algorithm?

Construct an example array such that this algorithm does not return the correct result. Explain what the correct result in your example should be and what the algorithm returns.

Answer text Question 2

Feedback

The running time is given by an arithmetic series and is thus Θ(n2).

A simple example where the algorithm would fail is A = [1, 4, 2, 3]. The algorithm would return 2 (sequence 1, 4 or 2, 3), when the correct answer is 3 (sequence 1, 2, 3). The algorithm is too greedy: when considering a sequence starting at i = 1,  it does not consider skipping A[2] = 4.

 

Information

Flag question

Information text

The problem can be solved with dynamic programming. Here is the recurrence for the length of LIS in A[i..n], with the condition that the elements of this LIS have to be larger than A[p] (p < i). The intuition is that A[p] is the last element included in LIS before solving the subproblem starting at i. The recurrence considers a binary choice concerning element A[i]: include it in LIS or not. The second line of the recurrence says that, if A[i] ≤ A[p], there is no choice – we have to skip A[i] and solve the remaining subproblem LIS(p, i+1). Otherwise, we have a choice of whether to take A[i] and solve the remaining sub-problem LIS(i, i+1) or to skip A[i] and solve the remaining subproblem LIS(p, i+1) (the third line of the recurrence).

LIS(p,i)=⎧⎩⎨0LIS(p,i+1)max(LIS(p,i+1),1+LIS(i,i+1))if i>n,if A[i]≤A[p],otherwise.LIS(p,i)={0if i>n,LIS(p,i+1)if A[i]≤A[p],max(LIS(p,i+1),1+LIS(i,i+1))otherwise.

The length of a longest increasing subsequence in A[1..n] is then LIS(0, 1) if we assume that A[0] = −∞. Note that p is always smaller than i.

Note that it is possible to answer the following questions even if you do not understand the intuition behind the recurrence.

Looking at the second and third rows of the recurrence, we can see that to compute LIS(p, i), we use LIS(p, ...) and LIS(i, ...). Note that i > p, thus we are using values from the same row or a row below (if p indexes over rows in the table), which means that the outer loop should go downto.

Similarly, for the inner loop, to compute LIS(p, i), we use values LIS(... , i +1). Thus, we also want to go downto  in the inner loop.
